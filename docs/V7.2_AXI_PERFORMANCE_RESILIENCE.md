# Trading AI Platform V7.2 — Axi Performance & Resilience

## Objective

Optimize for stable stage progression and funded-capital survivability rather than raw monthly return. The system must continue trading after Axi minimum profit/trade requirements are reached, but it shifts to smaller, shorter, higher-quality bets to protect accumulated gains.

## Current Axi Select baseline (verified 2026-08-27)

Primary/support sources:

- Pro: 7%, 60 days, 50 trades, max loss 7%, Edge 90, min equity $5,000
- Pro 500: 7%, 60 days, 50 trades, max loss 7%, Edge 90, min equity $10,000
- Pro M: max loss 10%, Edge 90, min equity $20,000; support documentation currently states a 10% profit target for progression/assessment while the marketing table may show no next-stage target. Treat this as a rule-source conflict requiring sentinel confirmation.

## Active Profit Protection

Reaching an Axi target does not disable trading.

- NORMAL: standard exposure.
- PROFIT_LOCK_ACTIVE: after target + trade count are reached, keep trading with a baseline size around 0.55x. Intraday opportunities are favored; long-duration position trades are penalized.
- RECOVERY: drawdown >=2% reduces size; no martingale.
- CAPITAL_PRESERVATION: drawdown >=3.5% or profit give-back >=25% reduces exposure to micro-size, not automatic zero.

Hard zero exposure remains reserved for the V7.1 hard-veto conditions (invalid/stale data, broker disconnect, extreme spread/slippage/volatility or capital-loss limits).

## Opportunity / Portfolio layer

The engine ranks candidates by:
- Master Decision score
- expected return/risk
- confidence
- liquidity
- transaction/execution cost
- portfolio correlation
- sector concentration
- systemic regime

Portfolio allocation then caps total risk and sector risk so multiple correlated BUY signals do not become one oversized macro bet.

## Crash Sentinel

Inputs include VIX/realized-vol z-scores, credit spreads, breadth, cross-asset correlation, liquidity stress, spread shock, safe-haven confirmation and geopolitical severity.

Regimes:
- GROWTH
- BALANCED
- DEFENSIVE
- CRISIS

DEFENSIVE and CRISIS reduce size first. Crisis mode permits cash, hedge or selective short/micro-size operation instead of automatically disabling the platform.

## Research debate

A Bull/Bear Research Judge compares the positive five-brain evidence with risk/event/price-extension arguments. Mixed evidence reduces size rather than automatically rejecting the trade.

## Data integrity

The point-in-time guard checks stale data, corporate actions, survivorship-bias control, duplicate news and source quality. Backtest data must only include information available at the historical timestamp.

## Execution

The execution optimizer chooses marketable-limit vs limit logic, order splitting and cancellation thresholds based on liquidity, spread, slippage and volatility.

## Learning / validation

Post-trade diagnosis classifies losses as forecast, regime-risk or exit-management errors. Strategy changes go to a Challenger first. A Challenger can replace the Champion only when expectancy improves materially without materially worsening drawdown and robustness tests remain acceptable (Deflated Sharpe / PBO inputs supported).

## Axi Rule Sentinel

The runtime sentinel checks trusted Axi primary/support pages every 6 hours (configurable with `AXI_SENTINEL_ENABLED=false`). It auto-activates a changed rule only when at least two trusted sources agree. If sources conflict or are unavailable, the last verified rule set remains active and the server logs a warning.

API endpoints expose current rules and a manual refresh:
- `GET /api/axi/rules`
- `POST /api/axi/rules/refresh`

This design intentionally prevents one malformed webpage from silently changing risk constraints.
